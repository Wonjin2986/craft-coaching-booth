선생님이 말로 소개할 부분

처음 60~90초. 화면의 문장을 모두 읽기보다 체험의 목적과 운영 이유를 설명합니다.

“안녕하세요. 저희는 AI 기반 학습자주도 수업 연구회입니다. 오늘은 선생님 수업에 필요한 학습지 한 쪽을 만들고, 학생에게 맞게 수정하는 것까지 해보겠습니다.”

“코칭이 낯설게 느껴지실 수도 있는데요. 질문을 통해 내 상황을 돌아보고, 어떤 방향으로 해볼지 스스로 정하도록 돕는 과정이라고 생각하시면 됩니다. 저희는 그 질문 방식을 자료를 만드는 과정에 연결해 봤습니다.”

“AI에 바로 ‘활동지 만들어 줘’라고 하기 전에, 우리 학생들이 어디에서 어려워하는지, 이 자료로 무엇을 할 수 있게 되면 좋을지 먼저 생각해 볼 겁니다. 그 생각이 자료를 만드는 기준도 되고, 고치는 기준도 됩니다.”

“오늘은 공용 PC라서 선생님 개인 계정으로 로그인하는 번거로움을 줄이고, 체험 중 무료 계정의 사용 한도 때문에 흐름이 끊기는 일을 줄이려고 마이클 계정을 준비했습니다. 로그인된 화면을 그대로 사용하시면 됩니다.”

“화면을 아래로 내려보시고, 떠오르는 수업 장면 하나로 시작해 주세요. 막히는 부분은 제가 함께 보겠습니다.”

CRAFT · 수업자료 제작 5단계

필요 탐색 → 자료 설계 → AI 제작 → 검토·보완 → 적용·성찰을 기억하기 위한 연구회의 제안입니다. 기존의 검증된 교수설계 모형을 뜻하거나 학술적 독창성을 주장하는 명칭은 아닙니다.

단계체험에서 할 일남길 기록
C · Context
필요 탐색		수업 장면과 학생의 어려움 탐색수업 장면, 대상과 주제
R · Requirements
자료 설계		기대하는 학생의 행동과 도움 정하기목표, 필요한 도움, 자료 형식
A · AI creation
AI 제작		요청문을 전달하고 초안 받기제작 요청문, 초안
F · Feedback
검토·보완		처음 목표를 보며 판단하고 수정하기검토 기준, 수정·유지 이유, 수정본, 확인 상태
T · Transfer
적용·성찰		활용 계획을 세우고, 수업 후 되돌아보기적용 계획, 추후 학생 관찰과 다음 수정 사항
“필요를 살피고, 자료를 설계하고, AI로 만든 뒤, 검토하고, 수업에서 적용하는 다섯 단계입니다. 저희는 이 과정을 CRAFT라고 이름 붙여 봤습니다. 오늘은 적용 계획까지 정리하고, 수업에서 써보신 후에 학생의 모습과 다음에 고칠 점을 기록해 보시면 됩니다.”

전체 흐름은 도입에서 한 번 제시합니다. 체험 중에는 현재 단계만 보이며, 검토·보완의 모든 화면에서 처음 정한 목표를 다시 보여줍니다. 마지막 화면·MD 저장·인쇄 모두 같은 다섯 단계로 정리됩니다. 목표에 맞지 않으면 ‘이전으로’를 눌러 설계를 다시 살필 수 있습니다.

말과 화면의 역할

시점진행자가 할 말화면에 남길 것
체험 전연구회 소개, 학습지를 만드는 목적, 코칭과 자료 제작의 연결, 마이클 계정 준비 이유연구회 이름·결과물, 스크롤로 읽는 코칭 설명과 질문 예시, CRAFT 전체 흐름
질문 작성답을 대신 정하지 않고 “그때 학생이 어떤 모습이었나요?”처럼 구체화를 돕기질문 하나와 앞선 답, 필요할 때만 펼치는 도움말
초안 제작마이클 탭과 모델 선택 위치를 5명에게 함께 안내GPT 6.1 SOL, 요청문 복사, 초안을 받은 뒤 돌아올 위치
검토·수정“이 부분을 우리 학생이 이해할 수 있을까요?”, 수정할 영역 선택 시연처음 정한 목표, 검토 기준·수정 이유, 수정 요청문, AI 한글 에디터 사용 순서
종료“어느 부분을 왜 고쳤는지” 짧게 나누고 파일 저장 안내CRAFT 단계별 제작 기록, 자료 확인 상태, 적용 계획, 기록 저장, 새 참여자 버튼

기본 체험 경로

코칭 질문 → 멀티 LLM · GPT 6.1 SOL → HWPX 학습지 초안 → AI 한글 에디터 → 검토·수정 → 한글 문서 저장

모델명은 선생님이 지정한 운영 기준입니다. 시작 전 실제 계정의 모델 목록에서 선택해 두세요. 웹 요청문은 편집 가능한 HWPX 파일 첨부를 명시합니다. A4 세로 1쪽, 본문 12~13pt, 실제 표·셀의 응답 칸 등 디자인 기준도 함께 전달합니다. 먼저 내려받은 HWPX를 확인한 뒤 에디터에서 엽니다. 본문만 나오면 제작 안내 화면의 ‘HWPX 추가 요청문 복사’를 사용합니다. 파일 생성 기능이 없는 환경에서는 학생용 빈 문서에 본문과 디자인 기준을 적용합니다.

마이클 공식 안내에 따라 수정할 영역을 선택하고 AI 편집 도우미에 요청한 뒤, 내용을 검토해 삽입하는 과정을 사용합니다. 한글 문서 저장 형식은 현장 계정에서 실제 제공되는 항목을 확인합니다. 학생용 빈 문서에서 진행하며, 가정통신문 머리말·학교장 명의·연락처가 들어가지 않게 확인합니다.

동선이 더 간단한 대안
리허설에서 한글 에디터의 초안 생성이 충분하면, 5대 모두 빈 문서나 양식을 열어두고 생성부터 수정까지 같은 문서에서 진행할 수 있습니다. 이때 멀티 LLM을 반드시 거칠 필요는 없습니다. 에디터 자체의 모델이 GPT 6.1 SOL이라고 가정하지 않습니다.

PPT를 고른 참여자

학생 설명용 슬라이드 5~6장의 원고와 화면 구성안을 만들고, 같은 대화에서 수정합니다. 이 경로의 결과물은 슬라이드 원고와 화면 구성안입니다. AI 한글 에디터로 PPT를 편집하거나, Canva·Google Forms 커넥터로 자동 제작하는 경로는 포함하지 않았습니다. 실제 PPTX 완성이 목표라면 파일 생성 가능 여부와 후속 편집 도구를 먼저 확인해야 합니다.

커넥터의 현재 목록·연동 예정 기능은 이번 체험의 핵심 동선에서 제외했습니다. 기능 소개보다 ‘어떤 학생에게 필요한 자료인가’에 집중합니다.

운영 시간 · 매시간 반복

정시~25분 체험 / 25~30분 휴식
30~55분 체험 / 55분~정시 휴식
정시와 30분에 시작하며 회차당 정원은 5명입니다.

25분 체험 진행안

0:00~3:00진행자 소개와 첫 화면 읽기
3:00~8:00수업 장면·대상·원하는 변화·필요한 도움 작성
8:00~14:00요청문 확인·복사, 마이클 초안 제작
14:00~21:00초안 검토, 구체적인 수정 요청, 한글 에디터 반영
21:00~25:00최종 확인, 활용 계획, 결과물·기록 저장

진행 목표이며 실제 측정값은 아닙니다. 소개 중 읽기 속도가 다른 참여자를 기다리게 하는 타이머나 자동 전환은 넣지 않았습니다.

PC 5대 준비

체험용 계정도 무제한으로 가정하지 않습니다. 동시 사용·제공량은 계정 조건에 맞춰 확인합니다. HTML 안에 계정 정보는 저장하지 않습니다.

5분 휴식 · 다음 참여자 준비

  1. 현재 참여자의 완성 문서와 제작 기록을 본인 기기로 가져갔는지 확인합니다. 공용 PC에 내려받는 것만으로는 자료 전달이 끝나지 않습니다.
  2. HTML에서 ‘새 참여자’를 눌러 질문 입력을 지웁니다.
  3. 마이클은 체험용 로그인을 유지하고 새 대화·새 문서를 엽니다.
  4. 이전 참여자의 대화·문서·내려받은 파일은 운영자가 정리합니다. HTML 초기화가 마이클 기록까지 삭제하지는 않습니다.

근거와 확인 범위

연구회 명칭: 사용자 폴더의 ‘2026. 미래교육 코칭 아카데미 활동 계획서’에서 확인.
코칭 소개: ICF의 코칭 정의를 부스 맥락으로 풀어 쓴 설명. 질문을 통한 자료 제작 체험이며 전문 코칭 전체를 대체하거나 검증된 교육 모형으로 주장하지 않습니다.
한글 에디터: 마이클 공식 사용 안내.
마이클 내 실제 생성·편집, 5대 동시 사용과 현장 소요 시간은 리허설에서 확인할 항목입니다.
